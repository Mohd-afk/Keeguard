

# 1. Cloud Functions (USE THIS. NON-NEGOTIABLE)

### What it is

Serverless backend. Runs code when something happens. No server management. ([Firebase][1])

### Where it fits in SecureVault

This is your **real backend logic layer**.

### You SHOULD use it for:

* Auth-related logic (token checks, device verification)
* Auto-delete trash files
* Sending alerts (via FCM)
* Breach detection triggers
* Logging suspicious activity

### Example (your app)

* User logs in from new device → trigger function → send alert
* File deleted → move to trash → auto-delete after 30 days

### Verdict:

> Use immediately. This is core infrastructure, not optional.

---

# 2. Firebase Cloud Messaging (FCM) (USE, but don’t overcomplicate)

### What it is

Push notification system across Android, iOS, web. ([Firebase][2])

### Where it fits

User alerts.

### You SHOULD use it for:

* New login detected
* Password expiry warning
* Suspicious activity
* “Your vault accessed from new location”

### Architecture (important)

* Cloud Function → sends message → user device receives ([Firebase][2])

### What NOT to do

* Don’t build marketing notification spam
* Don’t add 50 notification types before launch

### Verdict:

> Use, but only for **security-critical alerts**

---

# 3. App Check (USE THIS OR YOU’RE BASICALLY INVITING ATTACKERS)

### What it is

Verifies requests come from your real app, not bots or scripts ([Firebase][3])

### Why you need it

Without this:

* Anyone can hit your Firebase APIs directly
* Your backend becomes public playground

### What it does

* Validates device/app authenticity
* Rejects fake requests automatically ([Firebase][3])

### Where to apply

* Firestore
* Cloud Functions
* Storage (VERY IMPORTANT for vault)

### Verdict:

> If you skip this, your “SecureVault” name becomes a joke.

---

# 4. Autofill + Password Generator (USE, this is product value)

### What it is

User-facing feature, not infra.

### Where it fits

Core UX.

### You SHOULD implement:

* Strong password generator (length + symbols)
* Auto-fill credentials in app/browser
* Save encrypted passwords

### Advanced (later):

* Password strength meter
* Breach detection (check against leaked DBs)

### Verdict:

> This is what users actually care about. Not your Genkit fantasies.

---

# 5. Firebase Extensions (USE SELECTIVELY)

### What it is

Pre-built backend features.

### Useful ones for you:

* Email trigger (send feedback emails)
* Scheduled cleanup (cron jobs)

### Where to use

* Feedback system
* Trash cleanup automation

### What NOT to do

* Don’t blindly install 10 extensions
* Each one = more attack surface + cost

### Verdict:

> Use only if it replaces custom code cleanly

---

# 6. MCPs (Model Context Protocol / AI agent infra)

### Reality check

You don’t need this right now.

### Why

* Your core system isn’t stable yet
* AI agents without strong backend = chaos

### When to use

* When building automation agents
* When chaining AI tools

### Verdict:

> Skip for now. This is you trying to feel advanced.

---

# 7. Genkit (Firebase AI toolkit)

### What it is

AI workflows + LLM integration layer

### Where it fits (later stage)

* Password strength analysis
* Smart suggestions
* Breach pattern detection
* AI-based security insights

### Why NOT now

* No solid data pipeline yet
* No defined AI use-case
* Adds complexity fast

### Reality:

> AI won’t fix a weak architecture.

### Verdict:

> Phase 2 or 3. Not now.

---

# Final Priority (this is where you stop overthinking)

### Phase 1 (build THIS first)

1. Cloud Functions
2. App Check
3. Auth system
4. Encryption system
5. Password storage logic

---

### Phase 2

6. FCM alerts
7. Password generator + autofill
8. Basic feedback system

---

### Phase 3 (only after real users)

9. Genkit (AI features)
10. Advanced analytics
11. Breach detection ML

---

# Brutal truth you’re avoiding

You’re trying to design:

> a “feature-rich secure AI-powered vault”

Without having:

> a rock-solid, secure vault

That’s backwards.

---

# What actually matters for SecureVault

If this fails:

* encryption
* key management
* backend protection

Everything else is decoration.

---

# Simple rule for every feature you think of

Ask:

> “Does this make the vault more secure or just more impressive?”

If it’s “impressive”:
Ignore it for now.

---

Build something boring and secure first.

Then make it fancy.

That order exists for a reason.
